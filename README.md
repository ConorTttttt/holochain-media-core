# Holochain Media Core

Reusable, file-type-independent content contracts and security interfaces for Holochain Music, Video, and future applications.

**Status: CORE-004 technical milestone / pre-release (not production).** The workspace verifies Holochain Music S1 signed manifests and receipts (CORE-002), stores verified ciphertext in a resumable content-addressed store (CORE-003), and binds Holochain identity, discovery and certificate-pinned MoQ retrieval to that store (CORE-004), demonstrated by a real five-conductor acceptance suite. It does **not** encrypt files, evaluate or issue grants, approve publications, serve public media, or accept payments. Applications must not treat this library as an authorisation decision. See docs/CORE-004-holochain-moq-integration.md.

## Boundaries

- **Holochain:** signed identity, validated discovery and durable application metadata. No media payloads and no plaintext content keys on the public DHT.
- **Content Core:** immutable package/manifest contracts, provenance verification, storage integrity, access policy and lifecycle interfaces (introduced incrementally).
- **MoQ/QUIC:** peer-to-peer encrypted-content transport and ephemeral live streams. It is not an authorisation service.
- **Storage peers:** opaque ciphertext objects, signed receipt assertions and future availability/repair.
- **Music / Video:** codecs, playback, transcoding, creator interfaces and application-specific presentation.

The first implementation reuses Music's existing package/receipt formats through compatibility tests; it will **not** rewrite or silently migrate existing user data.

## Workspace

- crates/content-core: typed IDs, rights declarations, Music S1 verifier (compat), VerifiedCas (storage), Music S2 identity bindings (binding).
- crates/content-retrieval: transport-agnostic resolve/authenticate/resumable fetch into VerifiedCas.
- crates/content-cli: `holochain-media-core`, an opt-in local CLI adapter (public inputs only).
- crates/content-release: governed-release contract for Video (test-only authority).
- integration/: separate workspace with the MoQ client, conductor resolver and the real-service acceptance suite.
- docs/CORE-004-holochain-moq-integration.md, docs/CORE-004-video-integration.md: integration, quickstart, evidence, findings.
- docs/architecture.md: component responsibilities and boundaries.
- docs/contracts.md: compatibility baseline for Music's v1 signed packages.
- docs/current-state.md: audited repository dependencies and validation gaps.
- docs/threat-model.md: security assumptions and fail-closed rules.
- docs/roadmap.md: milestone/PR order and acceptance gates.
- docs/adr/: architecture decisions.

## Build

Requires a stable Rust toolchain with Cargo, rustfmt and Clippy.

    cargo fmt --all -- --check
    cargo clippy --workspace --all-targets -- -D warnings
    cargo test --workspace --all-targets

CI runs those checks on pull requests (also with `--features serde_json/preserve_order`). The real-service suite (Holochain conductors + MoQ hosts) runs locally; see docs/CORE-004-holochain-moq-integration.md. This repository has **not** been validated on a physical two-device network.

## Compatibility and migration

Music uses the signed wrapper and canonical JSON serialization in its Python module holochain_storage/package.py. CORE-002 verifies golden vectors generated by that code at a pinned commit. Music has an opt-in, disabled-by-default comparison adapter (holochain_storage/media_core_adapter.py on its CORE-004 branch); no production read/write path was switched. Video is unchanged.
